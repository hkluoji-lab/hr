# Agent Note：工作台跨两条阶梯的催办中心

Status: implemented

[English](2026-09-12-workbench-follow-up-center.md) | 中文

## 问题

阶段一 SOP 的催办执行 Skill（S-FOLLOW-01）正是前两个台账的交汇处：进入催办档位（T+3/T+7/T+14）的签转行与进入提醒档位（d30/d15/d7/d1/overdue）的义务行今天都需要催，但秘书只能在同一页的两个区块间来回盯，且没有任何地方记录「催过一次」这件事——重复跟进可能重复发送，也没人能回答「这家客户已被提醒过几次」。工作台需要一条跨两条阶梯的折叠催办队列、每个档位的 host 话术稿（SOP 的话术分档），以及一个记录每次提醒的登记动作。

## 决策

**一张 `reminders` 表在原位扩展 `workbench` 域，version 1 不变。** 每行存储 `targetKind`（`delivery`/`obligation`）、`targetId`、`tier`、`channel`、`message`（1–500 字符）与 `createdAt`，以随机 UUID 为键。提醒记录是只追加的历史而非状态：除了每个目标的次数与最近提醒时间戳，任何读取都不从存储的提醒派生。

**`followUps()` 在 host 把两条阶梯折叠为一个队列。** 处于催办档位的 open 签转行与处于提醒档位的 open 义务行成为以 `targetKind:targetId` 为键的行，join 客户当前名称。每行携带档位、该档位的建议渠道（`nudge` → whatsapp，`chase` → wechat，`escalate`/`d30`/`d15`/`overdue` → email，`d7`/`d1` → whatsapp——SOP 固定的档位-渠道映射）、按行事实填充的该档位中文话术稿、天数，以及已登记的提醒。行按固定严重度排序——`overdue` 最前，其后依次为 `escalate`、`d1`、`chase`、`d7`、`d15`、`nudge`、`d30`——使页面读起来就是今天的催办清单；同级并列按客户名再按标题打破。话术是面向客户的文案，因此无论工作台 UI 语言如何都保持中文。

**`recordFollowUp` 重新派生档位，不信任调用方。** 请求只命名目标加可选的渠道/话术改写；档位由当天日期对目标发出/截止日期重新计算，即使秘书晚几天补登记，记录仍然真实。队列渲染后目标已关闭的以 `workbench/follow-up-not-open` 拒绝；尚未进入阶梯的以 `gateway/bad-request` 拒绝；未知 id 以所属台账的错误码拒绝。渠道缺省为该档位建议，话术缺省为 host 稿——两者都接受秘书改写，这也是话术需要个人化时的日常路径。

**页面渲染一个带行内编辑的催办队列区块。** store 的读取变为五连（`workbench.followUps` 加入四连），`recordFollowUp` 在登记后刷新整个快照，使提醒次数来自 host 而非客户端派生。每行用 host 稿预填话术输入框、用该档位建议预填渠道选择器；行的 key 由 id *和*档位组成，档位变化时本地编辑状态重置为新话术稿，而不是残留旧文案。

## 曾考虑的替代方案

**在签转/义务行上存每目标的提醒状态。** 计数器或 last-chased-at 列能让队列折叠更快，但把历史冻结为可变状态，回答不了「当时发了什么」，且每加一条阶梯都要迁移。否决；按目标键控的只追加表让阶梯保持无状态。

**让客户端传入它渲染时的档位。** 读取与写入之间只要流逝了时间两者就会不一致，过期页面可能对已进入 `escalate` 的行登记 `nudge`。否决；host 在写入时重新派生。

**每目标每档位一行（upsert）。** 覆盖写能封住表的增长，但丢掉次数已经呈现的重复催办历史，还需要目标删除时的清理逻辑。否决；只追加行更简单，且每目标量很小。

**把话术稿移到客户端。** UI 里的话术会让 SOP 话术分档按 surface 分叉，wire 契约也无法提供缺省。否决；host 拥有文案，页面只做改写。

## 后果

旧介质以空 `reminders` 表原样打开。删除签转/义务不级联到其提醒——历史行保留目标 id，队列从活台账重算，孤儿提醒是惰性的。登记提醒从不推进目标本身：`signed` 的签转或 `submitted` 的义务仍需各自的生命周期动作，此前登记的提醒留作历史。队列永远不含纯提醒行——每行都投影一个今天处于某档位的 open 目标。

## 测试

Workbench host 测试覆盖折叠（fresh 行与远期义务隐藏、nudge 档位签转与 overdue 义务带建议渠道与话术稿入队、跨提醒阶梯的严重度排序）、登记（缺省派生档位/渠道/话术、接受秘书改写、拒绝未知目标、已关闭目标与未入阶梯目标）以及跨重启的持久化。客户端测试覆盖 store 往返（五连读取、登记动作刷新快照）与页面（队列渲染带档位徽章与提醒次数、可编辑话术与渠道选择器、登记动作、拒绝时的错误文案）。
