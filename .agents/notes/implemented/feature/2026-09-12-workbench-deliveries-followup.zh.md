# Agent Note：工作台文件签转台账与催办阶梯

Status: implemented

[English](2026-09-12-workbench-deliveries-followup.md) | 中文

## 问题

阶段一秘书公司 SOP 的文件签转 Skill（S-DELIV-01）要跟踪秘书发出的每一份待签署文件包——年报套装、合同套件——从发出、查看、签署到回收归档，并在客户沉默时按分级催办（T+3 提醒 / T+7 催办 / T+14 升级）。此前 host 侧没有任何地方记录一次发出：文件的下落只存在秘书的记忆或聊天历史里，没人能回答「发出了什么、等了多久」。工作台需要每次发出存一行、一个派生阶梯告诉跟进工作流每行今天所处的位置，以及一个读起来就是催办队列的页面区块。

## 决策

**`deliveries` 表就地扩展 `workbench` 域，version 1 不变。** spec 新增一个以随机 UUID 为键的 per-record 表；每行保存 `clientId`、`title`（1–120 字符，措辞由秘书负责）、`channel`（`email`/`wechat`/`whatsapp`，阶段一 S-CHAN-01 词表）、`status`（`sent`/`viewed`/`signed`/`returned`）与 `createdAt`。行在登记那一刻即以 `sent` 打开——没有草稿态，因为台账记录的是已经发出的文件，不是正在撰写的文件。早于该表的介质把它读成空表，既有部署原样打开。

**Remote 拥有 join、排序与阶梯派生。** `deliveries` 把每行 join 上客户当前名称，按 open 行在前（页面因此读起来就是催办队列）、各组发出最早在前排序，并在调用时派生 `daysSinceSent`（UTC 整天数）与 `followUpTier`：第一级之前为 `fresh`，未查看自第 3 天起为 `nudge`，未签署自第 7 天起为 `chase`，自第 14 天起为 `escalate`，行关闭后为 `done`。`markDelivery` 一次推进一个生命周期步骤——wire union 校验目标状态——`removeDelivery` 删除该行。阶梯从不入库：与申报阶梯一样，签转阶梯每次读取重新分级，不需要清扫器；在磁盘上把 `createdAt` 回拨后，旧行也会正确分级（测试在回拨介质上重启验证了这一点）。

**页面把阶梯折叠进一个队列区块。** `loadClients()` 变成四连读取（`workbench.deliveries` 加入原三连），快照携带各行，ClientsPage 新增文件签转区块：台账行带渠道、生命周期、已等待天数与阶梯徽章，每行一个单步推进控件（已查看 → 已签署 → 已回收；已关闭的行不再提供推进），以及三字段登记表单（客户、文件名称、渠道），必填字段不满足时提交控件保持禁用。文案经两种语言的 locale 字典路由；阶梯 CSS 类沿用申报阶梯「以 wire id 命名」的 CSS-module 模式。

## 已考虑的替代方案

**单独的 deliveries 包。** 这些行 join 的正是 workbench 域已拥有的客户主档；把台账拆出去会让一个外键跨插件却没有第二个消费者。否决；域就地扩展。

**带草稿行的多步登记流程。** 草稿态会让阶梯在尚未发出的行上开始计时，还需要清扫器清理过期草稿。否决；登记动作的含义就是「今天已发出」，因此行以 `sent` 打开且 `createdAt` 为现在。

**在行上存储每次催办的历史。** 阶段一 SOP 需要的是「今天该催什么」，不是审计线索；存储的历史会随每次催办增长，读取时反正还要挑出当前行。延期；阶梯按发出日期重算，催办记录属于后续真正执行动作（发邮件、发消息）而非只观察的工作流阶段。

**自由文本渠道。** 让秘书随意输入渠道字符串会让页面无法按渠道打徽章或过滤，且词表会按部署分叉。否决；阶段一由 wire 枚举固定 `email`/`wechat`/`whatsapp`。

## 后果

既有 `workbench` 介质以空 `deliveries` 表原样打开；删除客户不级联删除其签转行（行保留客户 id，客户行不存在时读取回退为原始 id），因此客户主档被删除后队列仍显示已发出的文件包。阶梯是派生的，不是记录的：在 `escalate` 停了一周的行只显示一枚徽章，而不是七枚。签转行是部署级的，没有按成员的归属，与本轮的客户端侧收窄一致。发出日期是登记时 host 的 UTC 日。

## 测试

Workbench 宿主测试覆盖签转 CRUD（默认渠道登记、全生命周期标记、删除、未知客户与未知签转拒绝）、以「等待最久在前、关闭行在后」的队列排序、跨阶梯边界（nudge/chase/escalate）的 tier 派生（含在回拨介质上重启）以及旧介质兼容。客户端测试覆盖 store 往返（四连读取、添加/标记/删除签转、wire 错误码拒绝）与页面（渠道/生命周期/阶梯徽章的行渲染、登记表单的本地校验与渠道载荷、作用域到所在行的推进与删除控件）。
