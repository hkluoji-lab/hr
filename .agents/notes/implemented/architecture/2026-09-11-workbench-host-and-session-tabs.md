# Agent Note: Workbench surfaces and the cross-plugin vocabulary seam

Status: implemented

English | [中文](2026-09-11-workbench-host-and-session-tabs.zh.md)

## Problem

The workbench product surface needed several contributions at once: a blank-session hero dashboard over the agent-preset roster; additive sidebar navigation to a task hall, a task assistant, an AI-team page, and a monthly report; host-owned credits state with a roster-presence aggregate the thin client cannot derive; and four session-scoped right-Sidebar tabs listing the session's produced files, its subagent children, the deployment's credits, and the team's live presence. The roster also gained four member presets whose names and descriptions must follow the client locale rather than the preset files. The produced-files tab also needed the exact accepted-call vocabulary `ui-deliverables` owns per turn, but client feature packages may not value-import one another's `./client` entry: `dsh-client-bundle-purity` rejects the cross-package runtime edge, and declaring the package in `dsh.client.external` fails `verify-client-packages` ("import shared types only or call an injected Cordis service").

## Decision

The workbench is one host package plus one client package, joined only by generated Remotes and Cordis services.

**Host capability.** `@deepseek-ai/dsh-workbench` (`packages/workbench/workbench`) defines the monotonic `workbench` storage domain v1, per-record layout: one nonnegative `credits` global (`{ balance }`, starting balance a Config field) and an append-only `entries` ledger keyed by random UUID. Its `Workbench` service extends `TypertRemoteService` under wire namespace `workbench` with three methods: `snapshot` returns credits beside the aggregated team, `ledger` returns the most recent grants newest-first bounded to `LEDGER_READ_LIMIT` (50) rows because the ledger only grows, and `addCredits(amount, reason)` validates a positive integer up to `config.maxGrant` and a bounded non-empty reason as `gateway/bad-request`, then appends the ledger row and replaces the balance global on the domain's single write chain. `team()` folds `agentPresets.list()` against live sessions exactly like the browser dashboard — broken presets are `offline` and sorted last, a preset is `busy` while a non-blank session (a started turn, via the `agentPreset` and `turnBoundary` projections) runs it, otherwise `online`. Both domain and aggregate live in the host; the browser never recomputes the join.

**Client surfaces.** `@deepseek-ai/dsh-client-ui-workbench` occupies existing extension points and owns no shell code. A `conversation.hero.dashboard` list entry renders the roster, quick actions, and the credits pill from one `workbench.snapshot` read that tolerates an unavailable Remote. Five additive `sidebar.footer.action` list entries — Workbench (the hero), Task hall, Task assistant, AI team, Monthly report — take their place in the existing sidebar foot without replacing its workspace or settings regions; the hero entry clears the current session, the other four toggle one page each. A `shell.overlay` list entry renders the open page across the frame; a closed state returns null, so the overlay layer keeps its click-through and no page intercepts input. The hall folds the Session list into task rows (skipping blank scratchpads and subagent children, newest first) and opens a row through `sessions.open`; the assistant collects a brief plus an optional member (default team when none), starts that session through the same staged-preset flow the member cards use, and submits the brief as its first user message; the team page reuses the hero roster and starts a session composed for a member's preset; the report tallies the local month's tasks and grants and grants new points through `workbench.addCredits`. Four `sidebarRightTabs` registrations — Deliverables, Progress, Credits, and AI team status — each carry a builtin tab definition plus a guide entry and a keyed session-scoped `sidebar.right.pane.tab` body, so the bodies exist only while a session is open. Deliverables memoizes a fold of the session event window on its revision; Progress holds no data and selects `origin: 'subagent'` session-list rows by parent, opening a child through `sessions.open`; Credits and AI team status bind the controller's ledger and dashboard snapshots, so they report deployment-wide balances, ledger rows, and member states rather than session state.

**Localized roster copy.** The shipped roster gains four member presets (`secretary`, `accountant`, `legal`, `audit`), each composing the standard toolset with its own persona. Their display names and descriptions are not read from `preset.yml`: `agent-presets` maps each built-in id to `BuiltInPresetCopyKey` entries and both dictionaries in `ui-agent-preset` supply the locale-owned copy, exactly as the pre-existing built-ins do, so no preset file carries user-visible text.

**Vocabulary seam.** `ui-deliverables` publishes `producedPathsFromEvents(events)` — the same per-turn accepted-call fold (`write`, `edit`, mutating `str_replace_editor`; skipping reads, failures, malformed calls, transient events; unique in first-seen order) with one call-id map covering every turn — and exposes it on the browser Context as the optional `sessionDeliverables` service whose `produced(events)` returns `{ path, name }` rows. The Workbench Deliverables tab type-imports only `ProducedFileEntry` and calls `ctx.get('sessionDeliverables')?.produced(events)`; a missing service is the explicit off state and renders the tab's empty line. This is the same optional-service pattern `chatFileMentions` already uses between ui-deliverables and ui-chat; it is deliberately not injected, so either plugin composes out independently.

**Wiring.** The web-app patch mounts `@deepseek-ai/dsh-workbench` as a host row and `@deepseek-ai/dsh-client-ui-workbench` as a browser plugin row; `api/remotes` mounts the service so the generated Typert client exposes `workbench.snapshot`, `workbench.ledger`, and `workbench.addCredits`. Package manifests, workspace tsconfig references, and the module-graph/tsconfig-path catalogs were regenerated. `@deepseek-ai/dsh-workbench/types` also needed a hand-written `tsconfig.base.json` alias to `src/types.ts`: the Client program otherwise resolved the built `./types` entry, and the typert analyzer — which maps a manifest export target back to its source path — then found no matching program file and crashed `gen-cordis-inspect-catalog`.

## Alternatives considered

**Value-import the fold from `ui-deliverables/client`.** This duplicated nothing but created a runtime edge between two browser feature packages; bundle purity failed and the edge would also freeze the vocabulary's bundle split. Rejected by both gates and by the package-boundary rule.

**Declare ui-deliverables under `dsh.client.external`.** `verify-client-packages` rejects runtime externals for client feature packages — only shared type imports or injected Cordis services are supported. Type-only imports give the types but no implementation, which is what the service pattern needs anyway.

**Reimplement the accepted-call vocabulary inside ui-workbench.** This passed the gates but forked the security-relevant "which tool calls count as produced files" policy; a new mutation tool would silently miss the tab and the two surfaces would drift. The optional Cordis service keeps one owner.

**Compute team presence in the browser only.** The hero already did this fold client-side, so a host aggregate looked redundant; persistence still required a host package for credits, and other surfaces (future non-browser clients, reports) need one host answer instead of re-deriving the preset/session join. The browser keeps its offline-tolerant roster read; the host snapshot is the single aggregate behind the credits pill.

**Add a page or route region to the shell.** A full-frame workbench page needs a seat, and no existing seat models pages. The slot registry refuses registrations into `root`, and teaching `ui-layout` about a page region would put one feature's navigation inside the shell. The existing `shell.overlay` list seat is documented as the additive frame-wide surface, so every workbench page rides it and the shell is untouched.

## Consequences

The cost is one new optional Context service and one host package: consumers must treat the service as possibly absent, and credits semantics (append-only ledger, bounded grants) are now a durable domain at v1 rather than client state. The gain is that the produced-files policy has exactly one owner, no client package value-imports a sibling's browser entry, the right-Sidebar contribution follows its [public two-stage registration](../feature/2026-09-04-right-sidebar-docking-infrastructure.md) without shell changes, and the Workbench tabs, hero, nav entries, and pages are ordinary slot occupants other compositions can remove independently. The pages are derived views, not new models: a hall task is a started session, the assistant page is a form that hands one brief to a session start, the team page re-reads the hero roster, and the report is a local-month tally over the loaded Session list and the bounded ledger page rather than a persisted report. The session tabs are views too: the deliverables fold covers only the loaded event window, progress lists direct subagent children rather than a workflow-run phase tree, and the credits and team-status tabs report the same deployment-wide snapshots the hero and report page show. The roster copy adds no new mechanism — the four member presets reuse the built-in-id → locale-key mapping, so a deployment that renames them in a dictionary changes every surface at once.

## Verification

Host behavior is pinned by `packages/workbench/workbench` tests (domain open/close, grant validation, ledger append, the bounded newest-first ledger page, busy/offline aggregation). Client behavior is pinned by ui-workbench hero, nav, assistant-page, page-view, store, tab, and plugin-registration specs, ui-deliverables session-fold and service-lifecycle specs, the agent-presets shipped-roster spec, and the ui-agent-preset locale spec; the keyless recorded-session suite still passes with the new keyed tab occupants and the overlay occupant. `verify-client-packages`, `dsh-client-bundle-purity`, `verify-client-catalog`, `verify-client-ui-i18n`, both TypeScript project aggregates, oxlint, the package README gates, and `hygiene` all pass; bundles were rebuilt and catalogs regenerated.
